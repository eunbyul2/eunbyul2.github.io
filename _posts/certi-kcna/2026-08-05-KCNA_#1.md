# KCNA #1 - 시험 소개와 학습 방향

## KCNA란?

**KCNA(Kubernetes and Cloud Native Associate)​**는 Linux Foundation과 CNCF에서 제공하는 Associate-level 자격증으로, Kubernetes와 Cloud Native 생태계에 대한 기본적인 이해를 검증하는 자격증이다.

CKA처럼 실제 Kubernetes 클러스터에 접속해서 `kubectl` 명령을 실행하고 문제를 해결하는 실기 시험은 아니다.

KCNA에서는 주로 다음과 같은 내용을 이해하고 있는지를 확인한다.

- Kubernetes의 기본 구조와 주요 컴포넌트
- Container Orchestration
- Networking / Storage / Security
- Application Delivery
- Observability
- Cloud Native Architecture
- CNCF Ecosystem

즉,

> **Kubernetes가 어떻게 동작하는지뿐만 아니라 Kubernetes를 둘러싼 Cloud Native 생태계가 어떻게 구성되어 있는지를 이해하는 시험**

이라고 볼 수 있다.

---

## CKA와 KCNA의 차이

나는 이미 CKA를 공부하고 취득했기 때문에 처음에는 KCNA가 단순히 CKA보다 쉬운 Kubernetes 입문 자격증이라고 생각했다.

하지만 실제 시험 범위를 살펴보니 두 시험의 방향에는 꽤 차이가 있었다.

### CKA

CKA는 Kubernetes 클러스터를 **실제로 운영하고 문제를 해결할 수 있는지**를 확인하는 시험이다.

```text
Kubernetes Cluster
        │
        ├── Cluster Architecture
        ├── Workloads
        ├── Networking
        ├── Storage
        ├── Troubleshooting
        └── 실제 Kubernetes 운영
```

시험에서도 직접 Kubernetes 환경을 다루면서 리소스를 생성하거나 수정하고, 문제가 발생한 클러스터를 Troubleshooting해야 한다.

### KCNA

KCNA는 Kubernetes 자체뿐만 아니라 그 주변의 **Cloud Native 생태계 전체를 조금 더 넓게 다룬다.**

```text
Cloud Native
│
├── Kubernetes Fundamentals
│
├── Container Orchestration
│   ├── Networking
│   ├── Security
│   ├── Storage
│   └── Troubleshooting
│
├── Application Delivery
│
└── Cloud Native Architecture
    ├── Observability
    ├── Cloud Native Principles
    ├── CNCF Ecosystem
    └── Community
```

따라서 CKA를 이미 공부한 나에게 KCNA는 Kubernetes를 처음부터 다시 배우는 과정이라기보다,

> **CKA에서 배운 Kubernetes 지식을 다시 정리하면서 Cloud Native 생태계 전체로 범위를 확장하는 과정**

으로 생각하고 공부하려고 한다.

---

## KCNA 시험 구조

현재 KCNA는 **온라인 감독 방식의 객관식 시험**으로 진행된다.

| 항목 | 내용 |
|---|---|
| 시험명 | Kubernetes and Cloud Native Associate |
| 약어 | KCNA |
| 시험 방식 | Online Proctored |
| 문제 형식 | Multiple Choice |
| 시험 시간 | 90분 |
| 응시료 | $250 |
| 재시험 | 1회 포함 |
| 시험 응시 가능 기간 | 구매 후 12개월 |
| 자격증 유효기간 | 2년 |
| 선수 자격 | 없음 |

CKA처럼 제한된 시간 안에 YAML을 작성하거나 `kubectl` 명령을 실행하는 시험이 아니다.

따라서 KCNA에서는 명령어 자체를 외우는 것보다는

**각 기술이 무엇이고, 어떤 역할을 하며, 서로 어떤 차이가 있는지를 정확하게 이해하는 것**

이 중요하다.

---

# KCNA Curriculum 변경

KCNA를 공부하면서 가장 먼저 확인해야 했던 부분이다.

인터넷에 있는 KCNA 자료 중 상당수는 이전 Curriculum을 기준으로 작성되어 있다.

기존 시험은 다음과 같이 **5개 Domain**으로 구성되어 있었다.

```text
Kubernetes Fundamentals            46%
Container Orchestration            22%
Cloud Native Architecture          16%
Cloud Native Observability          8%
Cloud Native Application Delivery   8%
```

하지만 **2025년 11월 이후 KCNA Curriculum이 변경**되면서 현재는 4개 Domain으로 구성되어 있다.

## 현재 KCNA 시험 범위

| Domain | 비중 | 주요 범위 |
|---|---:|---|
| Kubernetes Fundamentals | **44%** | Core Concepts, Administration, Scheduling, Containerization |
| Container Orchestration | **28%** | Networking, Security, Troubleshooting, Storage |
| Cloud Native Application Delivery | **16%** | Application Delivery, Debugging |
| Cloud Native Architecture | **12%** | Observability, Cloud Native Ecosystem & Principles, Community & Collaboration |

변경 전후를 비교하면 다음과 같다.

```text
Old Curriculum

Kubernetes Fundamentals            46%
Container Orchestration            22%
Cloud Native Architecture          16%
Cloud Native Observability          8%
Cloud Native Application Delivery   8%


                 ↓


Current Curriculum

Kubernetes Fundamentals            44%
Container Orchestration            28%
Cloud Native Application Delivery  16%
Cloud Native Architecture          12%
 └── Observability 포함
```

가장 큰 변화는 세 가지다.

### 1. Observability가 독립 Domain에서 제외

기존에는 `Cloud Native Observability`가 8%의 독립 Domain이었다.

현재는 별도의 Domain이 아니라 **Cloud Native Architecture에 포함**된다.

Observability 자체가 시험 범위에서 사라진 것은 아니기 때문에 Metrics, Logs, Traces 등의 내용은 여전히 공부해야 한다.

### 2. Container Orchestration 비중 증가

```text
22% → 28%
```

Networking, Security, Storage, Troubleshooting 등 Container Orchestration 영역의 중요도가 이전보다 높아졌다.

### 3. Application Delivery 비중 증가

```text
8% → 16%
```

비중이 두 배로 증가했다.

따라서 이전 KCNA 자료를 이용해서 공부할 경우 Application Delivery 영역을 너무 가볍게 보고 넘어가지 않도록 주의해야 한다.

---

# Domain 1. Kubernetes Fundamentals - 44%

KCNA에서 가장 높은 비중을 차지한다.

```text
Kubernetes Fundamentals
│
├── Kubernetes Core Concepts
├── Administration
├── Scheduling
└── Containerization
```

Kubernetes의 기본적인 구조와 동작 원리를 이해하는 영역이다.

Control Plane과 Worker Node의 역할, Kubernetes의 주요 컴포넌트와 리소스, Scheduling과 Container의 기본적인 개념 등이 포함된다.

CKA와 가장 많이 겹치는 부분이기 때문에 이 영역은 새로운 내용을 학습한다기보다 **기존에 공부했던 Kubernetes 개념을 다시 정리하는 방식**으로 진행할 예정이다.

---

# Domain 2. Container Orchestration - 28%

두 번째로 비중이 높은 영역이다.

```text
Container Orchestration
│
├── Networking
├── Security
├── Troubleshooting
└── Storage
```

Kubernetes가 Containerized Application을 운영하면서 필요한 Network, Storage, Security 등의 영역을 다룬다.

CKA에서도 각각 공부했던 내용이지만, KCNA에서는 개별 기능을 사용하는 방법보다는 **각 기술과 인터페이스가 어떤 역할을 담당하는지를 구분해서 이해하는 것**이 중요할 것 같다.

---

# Domain 3. Cloud Native Application Delivery - 16%

현재 Curriculum에서 비중이 크게 증가한 영역이다.

```text
Cloud Native Application Delivery
│
├── Application Delivery
└── Debugging
```

Cloud Native 환경에서 애플리케이션을 어떻게 배포하고 운영하는지를 다룬다.

Application Delivery를 공부하면서 CI/CD, GitOps, Declarative Deployment와 같은 개념들이 Kubernetes와 어떻게 연결되는지도 함께 정리할 예정이다.

---

# Domain 4. Cloud Native Architecture - 12%

비중은 가장 작지만 이번 KCNA 공부에서 개인적으로 가장 관심 있게 볼 영역이다.

```text
Cloud Native Architecture
│
├── Observability
├── Cloud Native Ecosystem and Principles
└── Cloud Native Community and Collaboration
```

Kubernetes 자체보다는 Cloud Native 환경을 구성하는 개념과 CNCF 생태계를 폭넓게 다룬다.

특히 기존 시험에서 별도 Domain이었던 Observability가 이 영역에 포함되어 있다.

Prometheus나 OpenTelemetry 같은 프로젝트도 단순히 이름을 외우기보다는,

> **어떤 문제를 해결하기 위한 프로젝트인지**

를 중심으로 정리할 예정이다.

---

# 어떻게 공부할 것인가?

KCNA는 객관식 시험이기 때문에 CKA와는 공부 방법도 다르게 가져가려고 한다.

CKA에서는 보통 다음과 같은 흐름으로 문제를 해결했다.

```text
문제 확인
   ↓
kubectl 명령 실행
   ↓
YAML 작성 / 수정
   ↓
리소스 상태 확인
   ↓
Troubleshooting
```

하지만 KCNA에서는 조금 다르게 접근해야 한다.

```text
문제 상황 확인
   ↓
어떤 영역의 문제인가?
   ↓
어떤 기술이 이 문제를 해결하는가?
   ↓
각 기술의 역할은 무엇인가?
   ↓
비슷한 기술과의 차이는 무엇인가?
```

예를 들어 단순히 CNI라는 단어를 외우는 것보다,

```text
CRI → Container Runtime
CNI → Networking
CSI → Storage
```

처럼 **각 Interface가 Kubernetes와 외부 구현체 사이에서 어떤 영역을 담당하는지를 구분해서 이해하는 방식**이 더 중요하다.

비슷한 Kubernetes Resource나 Cloud Native 기술도 같은 방식으로 비교하면서 정리할 예정이다.

---

# 이번 KCNA 공부에서 집중할 부분

CKA를 이미 공부했기 때문에 모든 영역을 동일한 깊이로 공부할 필요는 없다고 생각했다.

## Kubernetes Fundamentals

CKA에서 공부했던 내용을 복습한다.

단순히 명령어나 YAML 사용법을 다시 보는 것보다는 각 Component와 Resource가 **왜 존재하고 어떤 역할을 하는지**를 중심으로 다시 정리한다.

## Container Orchestration

Networking, Storage, Security와 Kubernetes의 연결 구조를 정리한다.

특히 CRI, CNI, CSI처럼 비슷해서 헷갈리기 쉬운 Interface와 Runtime 관련 개념을 확실하게 구분해서 공부한다.

## Cloud Native Application Delivery

CI/CD, GitOps, Declarative Deployment 등 Kubernetes 위에서 애플리케이션을 전달하는 과정을 정리한다.

기존 Curriculum보다 비중이 증가한 만큼 조금 더 자세히 살펴볼 예정이다.

## Cloud Native Architecture

이번 KCNA 공부에서 가장 새롭게 얻어갈 내용이 많을 것으로 생각하는 영역이다.

CKA에서 상대적으로 깊게 다루지 않았던 Observability, Cloud Native Principles, CNCF Ecosystem 등을 중심으로 공부한다.

---

# KCNA 공부를 시작하면서

처음에는 KCNA가 CKA보다 아래 단계의 자격증이라 이미 CKA를 취득한 상태에서 굳이 다시 공부할 필요가 있을까 생각했다.

하지만 Curriculum을 살펴보면서 두 시험의 목적이 조금 다르다는 것을 알게 되었다.

**CKA가 Kubernetes Cluster를 직접 운영하고 관리하는 능력을 중심으로 본다면, KCNA는 Kubernetes를 포함한 Cloud Native 생태계의 전체적인 구조와 개념을 이해하고 있는지를 확인하는 시험에 가깝다.**

그래서 이번 KCNA 공부의 목표는 단순히 자격증 하나를 추가하는 것이 아니다.

지금까지 공부하면서 각각 따로 알고 있던

```text
Kubernetes
Networking
Storage
Security
Observability
Application Delivery
CNCF Ecosystem
```

등의 개념을 **Cloud Native라는 하나의 큰 구조 안에서 다시 연결해보는 것**을 목표로 한다.

앞으로 각 Domain을 공부하면서 이미 알고 있는 Kubernetes 내용은 빠르게 복습하고, CKA에서 상대적으로 부족했던 Cloud Native 생태계와 주변 기술은 조금 더 자세히 정리해보려고 한다.
